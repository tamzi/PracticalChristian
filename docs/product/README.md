# Product documentation

Use these documents in the following order.

## Source of truth

- `docs/product/discoveryV2.md` - Product strategy, build sequencing, gating
  decisions, risks, and market-ready launch criteria.
- `docs/product/prd.md` - User outcomes, functional requirements, product
  boundaries, and quality requirements.

## Supporting documents

- `docs/product/featureList.md` - Capability-to-phase traceability matrix.
- `docs/product/competitorAnalysis.md` - Directional competitor research and
  research questions.

## Ownership boundaries

- Product strategy changes start in `discoveryV2.md`.
- Requirement changes update `prd.md` and then `featureList.md`.
- Architecture decisions belong in `docs/tech/technicalArchitecture.md` and
  `docs/tech/adr.md`.
- Delivery work belongs in `docs/tasks/workToBeDone.md`.

Supporting documents must not override the discovery document or PRD.
